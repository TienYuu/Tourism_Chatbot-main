================================================================================
🎯 GIỚI THIỆU
================================================================================

Đây là một hệ thống Knowledge Graph Reasoning cho các công trình di sản văn hóa, 
giúp trả lời các câu hỏi phức tạp qua việc duyệt đồ thị tri thức và suy luận 
ngữ nghĩa.

Mục đích: Trả lời câu hỏi tự nhiên về di sản văn hóa qua suy luận đồ thị  
Quy trình: Dữ liệu → 3 stage xử lý → Neo4j graph → QA Engine → Streamlit UI  
Kỹ thuật: Semantic parsing + Entity linking + Beam search + Embedding-based ranking  
Output: Câu trả lời có chứng cứ (với đường đi graph được xếp hạng)

(Wikidata)   (Trích xuất) (Chuẩn hóa) (Làm sạch) (Neo4j)  (QA Interface)

1️⃣ SemanticParser (reasoning/semantic_parser.py)
--------------------------------------------------

Chức năng: Chuyển câu hỏi thành cấu trúc structured JSON

Output ví dụ:
{
  "target": "Dinh Độc Lập",
  "question_type": "architect",
  "relations": ["architect"],
  "reasoning_depth": 1
}

Cơ chế: Dùng LLM (Groq) + fallback rule-based

Quy tắc nhận diện quan hệ:
- Property/attribute: coordinates, address, description, country
- Concept-related: material_used, architect, built_by, located_in

Quy tắc reasoning_depth:
- 1 = direct property lookup or single relation
- 2 = multi-hop reasoning path
- 3 = complex multi-hop constraints

---

2️⃣ EntityLinker (utils_new/entity_linker.py)
---------------------------------------------

Chức năng: Liên kết tên thực thể từ câu hỏi tới các nút trong graph

Cách làm: Fuzzy string matching (RapidFuzz) trên cache entities

Output: Entity ID, label, điểm tương tự

Phương pháp:
- Chuẩn hóa text (lowercase, normalize spaces)
- So sánh token_set_ratio giữa query và entity cache
- Lọc theo threshold (mặc định 80)

---

3️⃣ PropertyReasoner (reasoning/property_reasoner.py)
----------------------------------------------------

Chức năng: Trả lời câu hỏi thuộc tính đơn giản (không cần duyệt graph)

Ví dụ câu hỏi được xử lý:
- "Tọa độ của Dinh Độc Lập?" → Lấy latitude, longitude
- "Dinh Độc Lập ở đâu?" → Lấy address
- "Dinh Độc Lập là gì?" → Lấy description
- "Dinh Độc Lập ở nước nào?" → Lấy country

Điều kiện: Nếu trả lời được → trả lại luôn, không cần search graph

---

4️⃣ Planner (reasoning/planner.py)
---------------------------------

Chức năng: Tạo kế hoạch tìm kiếm dựa trên độ phức tạp của câu hỏi

Kế hoạch điều chỉnh:
reasoning_depth = 1 → max_depth=2, beam_width=5 (đơn giản)
reasoning_depth = 2 → max_depth=3, beam_width=8 (phức tạp)
reasoning_depth = 3 → max_depth=4, beam_width=10 (rất phức tạp)

Chiến lược: beam_search (tìm kiếm có hạn chế số lượng đường đi)

---

5️⃣ TraversalEngine (graph/traversal_engine.py)
----------------------------------------------

Chức năng: Duyệt đồ thị bằng Beam Search

Quá trình:
1. Bắt đầu từ entity gốc
2. Mở rộng hàng xóm (neighbors)
3. Lọc hàng xóm theo semantic (chỉ lấy quan hệ phù hợp)
4. Phát hiện và loại bỏ vòng lặp
5. Tạo nhiều đường đi song song (beam)
6. Lặp lại tới độ sâu max

Semantic Filtering:
- Nếu người dùng hỏi "ai kiến trúc sư"
  → Chỉ lấy edges có relation = "architect"
- Lưu trữ cache visited nodes để tối ưu

---

6️⃣ PathRanker (reasoning/path_ranker.py)
----------------------------------------

Chức năng: Xếp hạng các đường đi dựa trên điểm số

Công thức xếp hạng:
final_score = (
    relation_score × 0.55  +  # Quan hệ có khớp ý định?
    structure_score × 0.25 +  # Đường đi ngắn gọn?
    target_score × 0.20       # Loại entity đích khớp?
)

Thành phần:
- Relation Score: So sánh quan hệ trong graph vs ý định người dùng 
  (embedding similarity + hard mapping)
- Structure Score: Ưu tiên các đường đi ngắn hơn (1 - (length-1)*0.15)
- Target Score: Kiểm tra loại entity cuối cùng (semantic type matching)

Cơ chế:
- Sử dụng Sentence Transformers (all-MiniLM-L6-v2) để embedding
- Hard mapping: Nếu người dùng hỏi "vật liệu" → match với "material_used"
- Soft mapping: Embedding similarity cho các trường hợp mơ hồ

Relation Aliases (đồng bộ hoàn toàn):
architect: architect, designed by, kiến trúc sư, thiết kế, ...
built_by: built by, constructed by, xây dựng, ...
founded_by: founded by, sáng lập, người sáng lập, ...
located_in: located in, nằm ở, ở, ở đâu, vị trí tại
part_of: part of, thuộc, thuộc về, là một phần của, nằm trong
material_used: consists of, làm bằng, chất liệu, vật liệu, ...
time_span: time span, thời gian, vào năm nào, khi nào, niên đại, thời kỳ
related_to: related to, liên quan đến, đặc điểm của, thể hiện

---

7️⃣ RelationCanonicalizer (ontology/relation_canonicalizer.py)
-------------------------------------------------------------

Chức năng: Chuẩn hóa tên quan hệ từ nhiều biến thể

Ví dụ:
"kiến trúc sư", "designed by", "thiết kế" 
  → TẤT CẢ = "architect"
  
"nằm ở", "ở đâu", "vị trí" 
  → TẤT CẢ = "located_in"

Phương pháp: Keyword matching + lowercase normalization

---------------------------------------------

Chức năng: Ánh xạ NER labels → CIDOC-CRM classes

Bảng ánh xạ:
NER Label              | CIDOC-CRM Class
-----------------------|--------------------
PER                    | E21_Person
GPE/LOC                | E53_Place
FAC/HISTORICAL_RELICT  | E27_Site
EVENT                  | E5_Event
DYNASTY                | E4_Period
TIME                   | E52_Time_Span
ORG                    | E74_Group
ARTIFACT               | E22_Human-Made_Object
MATERIAL               | E57_Material
UNKNOWN                | E1_CRM_Entity

Semantic Keywords:
- MATERIALS: metal, alloy, steel, wood, stone, brick, ceramic, bronze
- BUILDINGS: tower, temple, pagoda, museum, monument, castle, fortress, bridge
- HERITAGE: heritage, historical site, archaeological site
- GEO: district, city, province, country, village, commune, ward
- NATURAL: mountain, river, lake, forest, island, beach, cave
- PERSON: human, person, architect, artist, king, emperor
- ORG: organization, company, agency, committee, association, university
- EVENTS: festival, battle, war, ceremony
- TIME: dynasty, historical period

🔀 LUỒNG XỬ LÝ MỘT CÂU HỎI (CHI TIẾT)
================================================================================

Ví dụ: "Ai là kiến trúc sư của Dinh Độc Lập?"

1. SEMANTIC PARSING
   Input: "Ai là kiến trúc sư của Dinh Độc Lập?"
   Output: {
     "target": "Dinh Độc Lập",
     "question_type": "architect",
     "relations": ["architect"],
     "reasoning_depth": 1
   }

2. ENTITY LINKING
   Input: "Dinh Độc Lập"
   Output: {
     "id": "independence_palace_001",
     "label": "Dinh Độc Lập",
     "score": 95
   }

3. PROPERTY REASONING (kiểm tra)
   → Không có thuộc tính "architect" trực tiếp
   → Chuyển sang graph search

4. PLANNING
   reasoning_depth=1 → max_depth=2, beam_width=5

5. TRAVERSAL (Beam Search)
   Start: independence_palace_001
   Depth 1:
     - independence_palace_001 -[architect]-> Nguyễn Viết Thụ
     - independence_palace_001 -[part_of]-> District 1
   
   Semantic Filter: Chỉ lấy edges architect
     - independence_palace_001 -[architect]-> Nguyễn Viết Thụ
   
   Depth 2:
     - Nguyễn Viết Thụ -[...]*-> ...

6. RANKING
   Path 1: independence_palace_001 -[architect]-> Nguyễn Viết Thụ
   score = 0.95 (khớp tuyệt đối)

7. ANSWER EXTRACTION
   Final Answer: "Nguyễn Viết Thụ"

💡 CHIẾN LƯỢC TRẢ LỜI CÂU HỎI
================================================================================

1. PROPERTY QUESTION (trực tiếp)
   Ví dụ: "Tọa độ của Dinh Độc Lập?"
   → PropertyReasoner trả lời ngay từ attributes
   → Không cần duyệt graph

2. SINGLE-HOP QUESTION (1 quan hệ)
   Ví dụ: "Ai kiến trúc sư của Dinh Độc Lập?"
   → EntityLinker: Tìm "Dinh Độc Lập"
   → TraversalEngine: Expand 1 level với filter architect
   → PathRanker: Xếp hạng kết quả
   → Trả lời: Nguyễn Viết Thụ

3. MULTI-HOP QUESTION (2+ quan hệ)
   Ví dụ: "Những công trình nào do kiến trúc sư của Dinh Độc Lập thiết kế?"
   → EntityLinker: Tìm "Dinh Độc Lập"
   → TraversalEngine: Expand 2 levels:
      Dinh → architect → Nguyễn Viết Thụ
      Nguyễn Viết Thụ → architect → Công trình khác
   → PathRanker: Xếp hạng tất cả kết quả
   → Trả lời: Danh sách các công trình

================================================================================
🎯 ĐIỂM NỚI BẬT CỦA HỆ THỐNG
================================================================================

1. SEMANTIC-AWARE SEARCH
   - Hiểu ý định người dùng qua semantic parsing
   - Lọc đồ thị theo quan hệ có nghĩa, không phải tuỳ tiện

2. MULTI-LANGUAGE SUPPORT
   - Xử lý cả tiếng Anh và tiếng Việt
   - Chuẩn hóa dạng khác nhau của cùng một quan hệ

3. EVIDENCE-BASED REASONING
   - Trả lời không chỉ kết quả mà còn đường đi
   - Người dùng thấy logic tìm kiếm

4. ADAPTIVE SEARCH DEPTH
   - reasoning_depth = 1 → tìm kiếm nông
   - reasoning_depth = 3 → tìm kiếm sâu & phức tạp

5. BEAM SEARCH OPTIMIZATION
   - Không phải tìm tất cả path (tốn thời gian)
   - Chỉ giữ top-K candidates tốt nhất (tối ưu)

6. ONTOLOGY-DRIVEN
   - CIDOC-CRM standard → khả năng interoperability
   - Clear semantic definition cho mỗi quan hệ

📊 KÍCH THƯỚC VÀ PERFORMANCE
================================================================================

Dữ liệu:
- Raw entities: ~1000s nodes
- Raw relations: ~10,000s edges
- After refinement: ~80% (duplicate removal)
- Neo4j indexes: id, label (performance optimization)

Performance:
- Entity linking: ~100ms (fuzzy matching + cache)
- Beam search (depth=2): ~500-1000ms
- Path ranking: ~100-200ms per path
- Total response time: ~2-3 seconds per question

Optimization:
- Entity cache (in-memory)
- Global visited set (prevent redundant expansion)
- Beam width limiting (stop exploring weak paths)
