Bạn cần thêm gì?
1. QUERY PLANNER (quan trọng nhất)

Thay vì:

{
  "reasoning_type": "location"
}

LLM phải sinh:

{
  "task": "find_location_hierarchy",
  "start_entity": "Tháp Eiffel",
  "target_constraint": "Paris",
  "max_hops": 3,
  "relation_types": [
    "P53_has_former_or_current_location"
  ]
}
2. DYNAMIC GRAPH RETRIEVAL

Thay vì:

get_location_hierarchy()

cứng.

Bạn cần:

execute_graph_plan(plan)

Ví dụ:

MATCH p =
(a)-[:P53_has_former_or_current_location*1..3]->(b)

được sinh động từ plan.

3. RELATION SEMANTIC MATCHING

User hỏi:

Tháp Eiffel nằm ở đâu?

LLM phải hiểu:

"nằm ở"
≈
P53_has_former_or_current_location
4. ENTITY LINKING thật sự

Hiện tại:

search_entity(keyword)

Chatbot thật cần:

Candidate generation
"Eiffel"
→ Eiffel Tower
→ Gustave Eiffel
→ Eiffel district
Candidate ranking

dựa trên:

semantic similarity
graph centrality
type matching
context
5. GRAPH EXPLORATION AGENT

Đây là bước lớn nhất.

Thay vì:

query -> answer

Agent sẽ:

Question
    ↓
Search node
    ↓
Expand neighbors
    ↓
Score paths
    ↓
Continue traversal
    ↓
Stop when evidence đủ

Giống:

GraphRAG
Microsoft GraphRAG
KG-Agent
Deep Research
Ví dụ thực tế

User:

Những công trình nào ở Paris được làm bằng sắt?

Hệ thống thật sẽ:

Step 1

Tìm:

Paris
sắt
Step 2

Graph expansion:

Paris
← location
Site
→ material
Iron
Step 3

Tự sinh Cypher:

MATCH
(site)-[:P53_has_former_or_current_location]->(paris),
(site)-[:P45_consists_of]->(iron)
